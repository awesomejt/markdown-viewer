# Decisions

## Purpose

This file contains a log of important decisions.

## 2026-10-11: Initial Scope And Stack

| # | Decision | Status | Rationale |
| --- | --- | --- | --- |
| D-1 | Deliver as a LAN web app; desktop wrapper deferred | Decided | Must work from an iPad and any LAN device. A browser is the only universal client. |
| D-2 | Files come from the server host and shares mounted on it | Decided (owner) | Simplest, most reliable way to reach network drives. No in-app SMB client or credential storage. |
| D-3 | No authentication (trusted LAN) | Decided (owner) | Home LAN use. Mitigated by read-only access, the root allowlist, and not exposing it to the internet. |
| D-4 | Viewer only, with live reload | Decided (owner) | Keeps the server read-only and simple. Editing may come later. |
| D-5 | Backend in Go | Decided (owner, 2026-10-11) | Native D2 library, single-binary deployment with the UI embedded, cross-compilation to NAS/Pi. Python would need the external `d2` CLI. The backend choice does not affect iPad access. |
| D-6 | React 19 + TypeScript + Vite frontend | Decided (owner preference for React) | Rich Markdown ecosystem. Static build embeds into the server. |
| D-7 | Markdown and Mermaid render client-side; D2 renders server-side | Decided (follows D-5) | Mermaid is browser-only. D2's maintained library is Go, and its WASM build is stale and heavy for an iPad. |
| D-8 | Live reload with fsnotify + polling fallback, delivered over SSE | Proposed | Network mounts often emit no change events. SSE is simple and reconnects in Safari. |
| D-9 | Desktop app: post-MVP. Prefer browser/web-app install, then Wails v3 (once stable), then Electron | Deferred | Wails v3 is still beta (beta.28). Electron is a heavier fallback. |
| D-10 | Voice-over script Markdown extensions considered after MVP, as remark/rehype plugins | Deferred (owner) | Useful for VO scripts (speaker labels, directions, timing, teleprompter). Needs research into existing conventions first. |
| D-11 | Deploy with Docker Compose on a VM server. NAS shares are mounted on the VM and bind-mounted read-only into the container | Decided (owner) | The owner's preferred target. The OS handles SMB/NFS. Network-mounted roots default to polling for live reload, because NAS-side changes emit no inotify events. |
| D-12 | Multi-agent delivery with model tiers (Haiku deterministic, Sonnet moderate, Opus judgment); one commit per task | Decided (owner) | Optimizes token usage. Tiers are assigned per task in `docs/Implementation.md`. |
| D-13 | Per-task Git workflow: clean `main` → feature branch → grouped commits with tests → quality gate → `--no-ff` merge → re-validate on `main`; no pushes without the owner | Decided (owner) | Keeps changes reviewable and grouped. Leftover branches signal an unfinished task. |
| D-14 | YAML preferred for config; all config/code linted (golangci-lint, ESLint, yamllint, markdownlint, hadolint, shellcheck); coverage ≥ 80% (fsroot ≥ 90%) | Decided (owner) | Owner preference for YAML and high test coverage. Missing host tools run as pinned Docker images. |
| D-15 | Build outputs under ignored `build/`; Vite bundle in ignored `internal/web/dist/` | Decided | `go:embed` cannot reference paths outside its package, so the bundle lives beside the embedding package. |
| D-16 | Track tasks in `TODO.md` and state in `status.yaml`; no Agent Workbench | Decided (owner) | Simpler for a single-owner project. `.awb/config.yaml` removed (f1ced02). |
| D-17 | Use TypeScript 6.0 (Vite template default) instead of 7.0 for now; `go.mod` uses `ignore ./web` | Decided | `typescript-eslint` 8.x pins TS 6. npm `flatted` ships Go files that `./...` would otherwise build and lint. |
| D-18 | Model tiers: Haiku = Git management + running tools (no authoring); Sonnet = coding, research, planning, per-task review; Opus = big reviews (🔒, phases), debates/challenges, escalations | Decided (owner) | In P0.1 and P0.2, Haiku authoring needed Sonnet rework and its reports overstated success. Supersedes the tier table from D-12. |
| D-19 | P0.6 plan hardening applied (C-1…C-15) | Decided | An Opus plan challenge found gaps in SSE connection use, dead-mount handling, file serving XSS, D2 imports and resource limits, path guard design, and sequencing. All 15 findings are applied to Architecture and Implementation. |
| D-20 | Env-only configuration in MVP (C-14); no YAML config file or `MDV_CONFIG` | Decided (owner) | Compose sets env vars directly, so a config file adds parsing and tests for no MVP gain. Revisit if the config grows. |
| D-21 | Minimal large-file "load anyway" button (`force=1`) in MVP, in F5 (C-11) | Decided (owner) | Without it, files over `MDV_MAX_FILE_BYTES` are unreadable in the UI. Only virtualized listings stay in R2.11. |
| D-22 | B2 path guard decisions | Decided | Raw `..` segments are rejected anywhere, with no rewriting. Input is never decoded twice, so `%2e%2e` is an ordinary name. Control, C1 and bidi characters, backslashes, drive letters and paths over 4096 bytes give 400. Escapes are detected from `os.Root`'s own error (fail-closed to 500 if Go changes it), special files give 403 (`O_NONBLOCK` + fstat), permission denied gives 403, ELOOP and ENOTDIR give 404, ENAMETOOLONG gives 400. Clients only see `PathError.PublicMessage()`, never host paths. |
| D-23 | B4a: fs callers wait for an in-flight slot instead of failing fast; file bodies are read through `Handle.Reader` | Decided (orchestrator, from Opus review) | Fail-fast made every 32 KiB read compete for the cap, so pages with more than 4 images got truncated bodies. One `MDV_FS_TIMEOUT` budget covers the slot wait and the op. A wait that expires is 504 `fs_timeout` but does not mark the root unavailable. Waiters spawn no goroutine, so stuck fs goroutines stay ≤ the cap. An unavailable root still fails fast. File metadata (ETag, size, 413) comes from an fstat of the opened file. |
| D-24 | F3b: Shiki highlights in the `pre` component after sanitize, not via `@shikijs/rehype` | Decided (orchestrator) | Shiki is async, so a rehype plugin would force react-markdown's async `MarkdownHooks` and break the sync render that anchor scroll and footnotes rely on. Plain code renders first and highlighted hast (converted to JSX, never `innerHTML`) swaps in. Core, engine (JS regex, no WASM), themes and each language load by literal dynamic `import()` from a fixed map. Dual themes switch via `data-theme` with no re-highlight. |
| D-25 | F4: Mermaid and D2 SVG are shown only as `<img src=blob:>`; Mermaid uses `securityLevel: 'strict'` + `htmlLabels: false` | Decided (orchestrator) | Diagram markup never enters the app DOM, so it cannot run scripts or reach app styles, whatever the renderer emits. `htmlLabels: false` avoids `foreignObject`, which `<img>` renders poorly (notably Safari). Trade-off: diagram text is not selectable and SVG links are inert. Mermaid renders are serialized (not reentrant). Diagrams re-render when `html[data-theme]` changes. |
| D-26 | R1 MVP review outcomes | Decided (orchestrator, from Opus review) | Cross-site and DNS-rebinding attacks through the LAN user's browser are in scope despite the trusted-LAN model: FIX-4 (D2 render CSRF + CSP) and FIX-5 (Host allowlist) block MVP sign-off. FR-1.2 date sort is a must-have, so it moves from R2.1 to FIX-11 in Phase 1. Remote `http(s)` images in Markdown load automatically (IP/time leak to third parties, `no-referrer` only); accepted for the LAN MVP. |
| D-27 | R2.13 Phase 2 review outcomes | Decided (orchestrator, from Opus review) | Phase 2 accepted with follow-ups. FIX-21 (root swap via symlink, 🔒), FIX-22 (bad sub kills the live stream) and FIX-24 (doc with 10 diagrams over 2 s, after FIX-23) should land before V1. An unmounted NAS shows as an empty root (mount point reopened, poll watchers report `deleted`) rather than unavailable: accepted, as documented in Architecture. Keyboard focus in a virtualized listing is lost when the focused row scrolls out of the overscan: accepted. NFR-3 numbers come from WebKit/Chromium emulation; the real iPad check is part of V1. |
| D-28 | FIX-24: NFR-3 doc render is measured as "what the user is looking at" | Decided (orchestrator) | Mermaid measures text in `document.body` (an off-screen container did not help), so each render costs ~200-380 ms in a 13k-node doc on WebKit and five serial renders cannot all finish in 2 s. NFR-3 is judged by `doc_nav_to_viewport_diagrams_ready` (jump to a mid-doc section until its Mermaid diagram is ready): 1.6-1.8 s on the iPad emulation. All diagrams still render (near-viewport first), so find-in-page and anchors are unchanged; all-10-ready (~2.6 s) is informational. Viewport-only lazy rendering and an iframe renderer were not adopted. Real iPad check in V1. |
| D-29 | Deploy on docker2 (192.168.50.58) under `/opt/stacks/mdv`, managed by a generic `docker-compose@<name>.service` template; the stack, not `docker.service`, waits for the NAS | Decided (owner request, 2026-10-14) | The VM will host other Compose apps, so Docker itself must not depend on this app's NAS mount. `stop` runs `compose down`, so Docker never auto-starts the container before the mount at boot. The mdv drop-in uses `Wants=`/`After=mnt-content.mount` rather than `RequiresMountsFor=`, so an automount idle unmount or NAS outage does not stop the stack. Server-local config (`.env`, `compose.override.yaml`) stays out of Git. |
| D-30 | Project files and layered settings (Phase 2b) | Decided (owner, 2026-10-14) | Projects are read-only `*.mdv.yaml` files inside roots, so they are shared across devices with no server write path (supersedes FUT2/FR-2.7). Settings layer as defaults < global `preferences.yaml` < project < device. Device text size is a per-device scale relative to the project/preferences size and never edits the project file; saving back is a later feature (FUT8). Cross-root references are planned (FUT7) but not in v1, and unresolved references must show warnings. |
| D-31 | Reading experience (Phase 2c): fonts are bundled OFL woff2 files served by mdv, not downloaded from the internet | Decided (orchestrator, owner request 2026-10-14) | Keeps NFR-5 (no internet at runtime, enforced by the e2e offline guard) and avoids leaking client IPs to font CDNs. Browsers fetch a font from mdv only when it is used and cache it, which gives the owner's download-once behavior without a prompt. Rejected: a one-time prompt to fetch fonts from the internet (breaks offline use and the guard). Styles are mdv's own token CSS inspired by Typora/VS Code previews, not copied themes. Read time is computed client-side from the mdast; focus mode is the base for the VO-5 teleprompter. |
| D-32 | Read time defaults to 160 wpm; `readTime` settings live in preferences and projects only; teleprompter is a later feature (FUT9) | Decided (owner, 2026-10-14) | 160 wpm is the owner's measured script-reading speed. Some scripts are read aloud from code blocks, so `includeCode` is a per-project option (default off). Read-time rates are not a device adjustment. The teleprompter scrolls at the read-time rate by default with live adjustment, Space to play/pause and the wheel to move, and builds on focus mode. |
| D-33 | PJ0 contract for projects and preferences (Phase 2b) | Decided (owner answers and Opus challenge, 2026-10-14) | Library `go.yaml.in/yaml/v3` v3.0.4 (maintained fork, in the module cache). Files are parsed by walking a `yaml.Node` tree, not `KnownFields`, so unknown keys become warnings with lines; anchors, aliases, tags, merge keys and extra documents are fatal, and the decoder only reads bytes already read (reader errors can embed host paths). Limits: 32 KiB, depth 8, 2000 nodes, 200 includes, 100 warnings, 4 parallel parses. Reference resolution shares one stat limiter per root, singleflight and a poll-interval TTL across requests so a project cannot fan out stats. A project stays active within its root until an explicit exit, and a broken live edit keeps the last good project with an error line. Device choices for theme and listing toggles are per project inside a project and global outside (text scale stays one global value), with one Reset control; a one-time migration drops stored values equal to the old defaults. Both `.mdv.yaml` and `.mdv.yml` are accepted. |
| D-34 | PJ9 Phase 2b review outcomes | Decided (orchestrator, from Opus review, 2026-10-16) | Phase 2b accepted with follow-ups FIX-30 to FIX-35 and DOC3; FIX-30 (demo `open` flagged not in project) and FIX-31 (Home link unreachable at 320 px) land before V1. Inside a project only that project's device choices apply (PJ0 orchestrator call, kept; DOC3 documents it). Accepted: a reference into a hung sub-mount can hold both stat-limiter slots of its root, after which projects in that root report references `unavailable` after the 2 × `MDV_FS_TIMEOUT` wait (`/api/file` unaffected); YAML library messages may echo an anchor name from the file (sanitized, 200 runes); settings apply in `useEffect` (one possible frame of old values); a reloaded project's theme is not cached, so the shell shows the prefs theme until the project loads. Real iPadOS hardware-keyboard behavior (Cmd `+`/`−` vs Safari zoom) goes on the V1 checklist. |
